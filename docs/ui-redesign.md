# AIGate 管理面板 · 前端重设计方案

> 本文是**设计方案**，不含实现。基于两份独立取证：
> ① WaLiAPI 前端设计模式研究（commit `3fcc40f`，MIT，静态审阅未运行）；
> ② AIGate 自身前端审计（28 项结构性问题 + 5 个已逐条核实的真 bug）。
> 量化基线来自 `tools/audit_ui_density.py`（无头浏览器实测渲染高度）。
>
> 硬边界（不能动的）：Alpine.js 3 + 内联 Tailwind（**无构建步骤**）+ 切片 `concat!` 拼接 + 单 exe + Windows 内嵌 WebView。
> 所以本方案不引入 React 组件库、不引入打包器、不引入图表库。

---

## 0. 一句话结论

**问题不是"控件不好看"，而是缺少一套统一的「信息分级 + 状态语义」规则。**

具体表现：同一个指标有 4~7 个入口、5 种单位；「面板标题」有 4 个类名 4 个字号；20+ 个面板没有标题；
65 处可点元素里 60 处键盘不可达；设置页同一屏里两种生效语义（点即生效 vs 必须保存）外观完全一样。

所以方案的核心**不是**换皮，而是定三条规则，然后用它们把六个页面重排一遍：

1. **每屏只留一个"主问题"** —— 每个页面先回答一个问题，其余信息降级或折叠。
2. **同一指标只有一个权威入口** —— 其他位置只能引用，不能各画一张。
3. **状态必须可见且可区分** —— 未保存/测试中/测试失败/熔断中/凭据失效/加载中/拉取失败，
   每种都要有独立、就地、不自动消失的表达。

## 2. 已核实的真 bug（不是设计问题，但必须一并修）

这 5 条我逐条用 grep 核实过，不是转述：

### B1 `healthOf` 判定值自相矛盾 → 「测试并恢复」按钮可能永不出现

```
drawer-provider.html:13  healthOf(...)==='ok'
drawer-provider.html:14  healthOf(...)==='error'   ← 永远为假
drawer-provider.html:15  healthOf(...)===''
drawer-provider.html:38  healthOf(...)==='err'     ← 实际值是这个
```
`healthOf` 实现（`ds-core.js:272`）返回 `h.status_level`，真实取值是 `ok`/`err`。
→ **L14 那个「连接错误」徽章分支永远不命中**；L38 才是对的。

**影响**：抽屉头部永远显示「未连接」，或熔断后唯一能解除的按钮不出现。
**修**：把 `'error'` 改成 `'err'`，并抽一个 `healthState(name)` 返回枚举，禁止各处比字面量。

### B2 高峰计费/Tooltip 的未保存改动被静默覆盖，而「未保存」标记不复位

```
page-settings.html:130  点开关只置 peakDirty=true（不落盘）
ds-core.js:223          切页签时 fetchPeakSchedule() 用后端值覆盖本地
ds-config.js:162        peakDirty 只在保存成功时置 false
ds-core.js:205          isDirty 守卫只对 providersFormData，不含 peakDirty
```
**影响**：改了高峰时段 → 切去看供应商 → 回来设置变回原样，但黄色「未保存」还挂着。
用户既丢了改动，也不知道该不该再点保存。
**修**：`peakDirty`/`tooltipDirty` 纳入 `switchTab` 的离开确认；覆盖前先判断 dirty。

### B3 localStorage 白名单漏键 → 每次升级重置用户的列显隐与每页条数

```
ds-core.js:56   KEEP = {cache-version, analyticsSpan, aigate_drawer_adv, chartMode, theme}   ← 5 个
实际写入 6 个:  + aigate.pageSize (core.js:212)  + aigate.logCols (ds-records.js:228)
```
`ds-core.js:60` 会删掉所有不在白名单里的 `aigate*` 键。
**影响**：用户设的列显隐、每页条数每次版本变化都被清掉，且无任何提示。
**修**：白名单改为"声明式注册"——由各模块注册自己的键，统一收口；或直接把两个键补进 KEEP。

### B4 `filteredModelStats` / `modelDetailProviders` 各定义两次，后者覆盖前者

```
ds-stats.js:77  / ds-stats.js:86      ← 被覆盖
ds-computed.js:499 / ds-computed.js:509  ← 实际生效（拼接顺序在后）
```
**影响**：模型明细的供应商筛选对"无 provider 字段"的行行为随拼接顺序变化，筛选结果与列表显示不一致。
**修**：删掉 `ds-stats.js` 那份，只留一份。

### B5 引用了不存在的 CSS token

```
--fs-16  被 drawer-provider.html:10、components.css:678 引用
         实际字阶只有 --fs-9/10/11/12/125/13/14/15/18  ← 无 16
--line   被 modal-add-fetchdiff.html:6 引用，未定义
```
**影响**：供应商名称输入框与空态标题脱离字阶；预设条目边框回落 `currentColor`（随上下文变色）。
**修**：改用既有档位（`--fs-15` 或 `--fs-18`）；`--line` 改 `--border`。

## 3. 设计原则（三条，可判定）

### 原则 1：每屏一个主问题

| 页面 | **主问题**（首屏只回答它） | 次要信息去向 |
|---|---|---|
| 概览 | 「现在有没有问题？」 | Hero 带 + 健康一句话；其余折叠 |
| 分析 | 「用量/省量/性能趋势如何？」 | 页签分开；诊断类默认折叠 |
| 记录 | 「刚才那次请求怎么了？」 | 表格 + 详情（渐进披露） |
| 供应商 | 「哪些供应商能用？哪个坏了？」 | 列表 + 抽屉编辑 |
| 设置 | 「我改的这项生效了吗？」 | 分区 + 每项自带生效说明 |

**判定方法**：打开页面 3 秒内，用户能否不看滚动条就回答这个问题。做不到就是没做到原则 1。

### 原则 2：同一指标只有一个权威入口

现状重复（已审计）：

| 指标 | 入口数 | 口径种类 |
|---|---|---|
| 成功率 | 4 | 3（今日 / 窗口 / logs 数组） |
| 平均延迟 | 5+ | 2 |
| Token 总量 | 6 | 3 |
| 优化省量 | 5 | 5 种单位组合 |
| 费用 | 5 | 2（含币种换算） |
| 请求数 | 4 | 3 |
| 供应商/模型数 | 7 | — |
| Base URL | 4 | 且**复制状态串台** |

**规则**：
- 每个指标指定**一个权威位置**（见 §4 的分配表）；
- 其他位置**只允许引用**（显示"见 X"，或显示同一个数但**必须标注同一口径**）；
- 口径不同的，**必须**在数字旁标注（如「今日」「窗口 5000 条」「本页 20 条」）；
- 复制状态按**用途分键**（`base-quickstart` / `base-apimeta` / `base-settings`），不再共用 `copiedField==='base'`。

### 原则 3：状态必须可见、就地、不自动消失

现状：`providersFormMsg`/`keyMsg`/`currencyMsg`/`providersFormOk` **全部 0 处 HTML 渲染**，
靠 `$watch` 转成 3 秒 toast。`balanceLoading`/`healthLoading` **0 处渲染**（点刷新按钮毫无反馈）。
拉取失败被 `catch(e){}` 吞掉 → 显示成"没配置"。

**规则**：每个可变更对象（供应商、设置项、缓存、余额）都有一个**状态行**，
就地显示：`未保存 / 保存中 / 已保存（时间）/ 保存失败（原因）/ 加载中 / 拉取失败（原因）`。
toast 只用于"动作已触发"，不作为唯一反馈。

## 4. 信息架构：六页重排

### 4.0 全局骨架

保留现有「顶部胶囊导航 + 全宽内容」（这已经是对的设计，比左栏省横向空间）。

新增两项全局改进：
- **布局宽度统一**：`.ov-page` 当前是 `max-width:none`（会无限拉伸），其余页 `1600px` 封顶
  → 统一为 `max-width:1800px`，超宽屏不再出现"两类页面行为相反"。
- **全局状态条**（顶栏右侧，替代部分 toast）：一个常驻小区域显示最近一次动作的结果，
  可点击展开历史（最近 10 条）。这解决"3 秒后无从回溯"的问题。

### 4.1 概览：从 7 面板 → 3 区块

现状 1747px / 7 面板 / 11 个首屏按钮。**主问题：现在有没有问题？**

```
┌─ Hero 带（保留现有设计，已对照 cc-switch）───────────────────┐
│ 今日 Token（主数字）  │ 请求 · 费用 · 成功率 · 缓存命中        │
└──────────────────────────────────────────────────────────────┘
┌─ 一句话结论 ────────────────────────────────────────────────┐
│ "一切正常" / "go 供应商连续失败 3 次，已熔断" / "成功率 92%，低于昨日" │
│   ↑ 替代现在散在 4 个面板里的 takeaway                          │
└──────────────────────────────────────────────────────────────┘
┌─ 两列：左「供应商健康」右「最近发生的事」────────────────────┐
│ 供应商：每行 = 名字 + 状态点 + 余额 + 今日花费（Top-8 + 更多→）  │
│ 事件：最近 6 条（原 8 条压到 6），折叠"查看全部"                │
└──────────────────────────────────────────────────────────────┘
[折叠] 接入引导（3/3 完成后自动收起，保留现有行为）
[折叠] 趋势图 + 热力图（默认收起，点"看趋势"展开）
[折叠] FAQ
```

**关键改动**：
- 删除「性能健康」独立面板（541px）—— 其 4 个指标并入 Hero 的指标簇 + 一句话结论；
- 「API 信息」「快速开始」合为一张卡，置于页尾（新用户才需要，不是日常信息）；
- Base URL 只在这一张卡里出现，**复制键独立**。

### 4.2 分析：两个页签 → 三页签（按"问题"分，不按"数据类型"分）

现状 1634px / 5 面板 / 诊断（p95、最慢节点、TTFT 直方图）常驻首屏。

```
页签 1「用量」  → 主问题：用了多少？        Token 趋势 + 热力图 + 模型/供应商排行
页签 2「省量」  → 主问题：省了多少、还能省哪？  省量审计（含新增的上下文构成）
页签 3「性能」  → 主问题：慢在哪？           链路拓扑（含 TTFT 分位）
```

**关键改动**：
- 「链路拓扑」从常驻改为**页签内**（它回答的是"慢在哪"，不是"用了多少"）；
- 「省量审计」内部再分层：首屏只给"已生效省量 + 占比"，分项/潜在可省/上下文构成/输出侧 **折叠**；
- 「模型明细」表从 13 列 → **默认 7 列**（模型/供应商/请求/输入原始→实发/输出/费用/省量），
  其余进「更多列」；诊断四值已在上一轮合并为一格。

### 4.3 记录：保留（这一页结构最健康）

现状 1742px / 1 面板 / 表格 9 列 / 详情弹窗 6 个诊断块全铺。

**唯一改动**：详情弹窗按"回答顺序"重排，并把诊断折叠：

```
[必须] 时间 · 模型 · 供应商 · 状态 · 耗时
[必须] 输入(原始→实发) · 输出 · 费用
[折叠] 结束方式 · 上游尝试 · 阶段耗时 · 网关去程 · 上下文构成
[折叠] 错误详情
```

### 4.4 供应商：从"表格 + 全屏抽屉"→ "列表 + 行内展开 + 详情抽屉"

现状：一行最多 8 个按钮；最短闭环 4 层界面 8 次点击。

```
列表行（默认）: [状态点] 名称  模型数  成功率  [测试]  [编辑]  [⋯]
              ↑ 点整行展开行内摘要（不跳界面）
行内摘要（展开后）:
  端点 · 当前密钥来源（草稿/已保存） · 熔断状态
  [⚡ 测试] 结果就地显示（绿/红条 + 环节 + 延迟，不消失）
  [编辑] → 抽屉（保留）
```

**关键改动**：
- 8 个按钮 → **3 个**（状态/测试/编辑）+ 1 个「⋯」菜单（删除/重置熔断/拉取模型/登录）；
- 整行可点 = 展开行内摘要（**不是**直接开抽屉）；
- 测试结果**就地持久**（不再刷新即消失）；
- 「⋯」菜单里危险项标红 + 二次确认。

### 4.5 设置：48 控件必须收敛

现状 2766px / 2.77 屏 / 48 可点控件 / **同屏两种生效语义**。

```
左：分区导航（5 项，sticky）        右：单个分区的设置
  性能与优化                        每项一行：名称 + 说明 + 控件 + 状态标记
  thinking 提纯                     ↑ 状态标记 = 即时生效的显示"已生效"，要保存的显示"未保存"
  响应缓存
  分时段计费
  连接与监控
```

**三条硬规则**：
1. **一种语义**：全部改为**即时生效**（取消高峰/Tooltip 的"必须保存"）。
   理由：同一屏两种语义是当前最大的困惑源，而"即时生效"是多数模块的现状。
   若某项确实不能即时（如改高影响计费），则**整块**移到一个明确的"高级设置（需保存）"区，
   与即时区物理分开，不混排。
2. **每项带状态标记**：`已生效` / `未保存` / `保存中` / `失败(原因)` 四种之一，就在该项右侧。
3. **数字输入统一走 `onNumInput`**：现状 9 个走、4 个不走（`tz_offset_hours`/time/`update_interval_secs`）。

### 4.6 关于：保留

现状已合理（956px / 5 面板）。只需修标题层级（见 §5）。

## 5. 控件规范（统一，消除 4 套标题、65 处键盘不可达）

### 5.1 标题层级（现在有 4 个类名 4 个字号）

| 层 | 用途 | 尺寸 | 语义标签 |
|---|---|---|---|
| L1 | 页面标题 | `--fs-18` | `<h1>` |
| L2 | 面板标题 | `--fs-15` | `<h2>`（**现在 `.pnl-ht` 是 `<span>`，屏幕阅读器跳标题会跳过所有面板**） |
| L3 | 分区/分节标题 | `--fs-12` | `<h3>` |

**统一**：`.pnl-ht` / `.st` / `.about-section-title` / `.sub-h` 四个类名合并为 `--fs-15` 一套，
全部改成真实标题标签。20+ 个无标题面板补标题。

### 5.2 可点元素（65 处里 60 处键盘不可达）

| 现状 | 问题 | 规范 |
|---|---|---|
| `.seg-i` 分段页签 | 无边框无底色，只有选中态有底色 | 改为**带边界的胶囊**（默认就看得出来能点） |
| `.m-chip` 筛选胶囊 | 透明底 + muted 色 | 默认给 `1px` 边框；选中态实底 |
| `.th-sort` 表头 | 只有 hover 变色 | 加排序箭头图标（常驻，非 hover 才现） |
| `.bdg-click` | 形状是徽章 | 保持徽章形，但加 `cursor:pointer` + 下划线 |
| `<td @click>` 诊断格 | 纯文本 | 加"可展开"指示（▸） |
| `.tgl` 开关（**11 个全裸**） | 无 `role`/`aria-checked`/名称 | 统一加 `role="switch" aria-checked aria-label` |

**统一规则**：所有可点元素必须满足——① 有可见的"可点"指示；② 键盘可 Tab 到；
③ 有可及名（`aria-label` 或内部文字）；④ Enter/Space 可触发。

### 5.3 按钮层级（现在全站 3 种视觉档）

| 档 | 用途 | 样式 |
|---|---|---|
| 主 | 每个视图最多 1 个（保存/测试） | 实底强调色 |
| 次 | 常用操作 | 边框 + 前景色 |
| 弱 | 低频/折叠 | 边框最淡（**现在的 `.btn-g` 太淡，看起来像文字**） |

**改动**：`.btn-g` 的 `border-subtle` 太淡 → 提到 `--border`，并加 hover 底。

## 6. 可迁移的模式（按性价比排序，来源 WaLiAPI）

| 优先 | 模式 | 一句话 | 难度 | 是否需要改后端 |
|---|---|---|---|---|
| 1 | **Top-N + 溢出链接** | 列表只渲染前 N，底部"还有 N 个 →" | 低 | 否 |
| 2 | **数据量驱动默认收敛** | `<=5` 展开、`>140` 才给"展开"、`>8` 才给"更多" | 低 | 否 |
| 3 | **指标降级带** | 弱指标并成一行文字，替代新增卡片 | 低 | 否 |
| 4 | **可见性+阅读态感知轮询** | 页面不可见或有展开项时暂停刷新，偏好落库 | 低 | 否 |
| 5 | **陈旧响应守卫 + 防抖** | 自增序号丢弃乱序响应；输入 300ms 防抖 | 低 | 否 |
| 6 | **就地复制反馈** | 点击复制 → 按钮内打勾 1.2s（按用途分键） | 低 | 否 |
| 7 | **dry-run 计数确认** | 危险操作先返回影响行数再执行 | 低 | **是**（加 dry_run 参数） |
| 8 | **表头"更多列"单开关** | 次要列默认藏，表头一格切换 | 低 | 否 |
| 9 | **固定布局表格 + 单元格两行** | 百分比列宽免横滚；主值上、辅值下 | 低 | 否 |
| 10 | **可读/源数据双视图** | 同一 payload 两视图 + 免责说明 | 低 | 否 |
| 11 | **哈希锚点 Tab 深链** | Tab 状态与 `location.hash` 双向同步 | 低 | 否 |
| 12 | **保存闸门（草稿测试）** | 保存前跑真实测试，全过才落库 | 中 | **是** |
| 13 | **测试凭证指纹** | `test_run_id + fingerprint`，字段一改即失效 | 中 | **是** |
| 14 | **逐端点结果卡** | 每端点一行：状态色/类别/延迟/计费提示 | 低 | 否 |

## 7. 分期落地（每期可独立验收、可回滚）

### 期 0：修真 bug（不改设计，1 个提交）

- B1 `healthOf` 判定值（`'error'` → `'err'`，并抽 `healthState()`）
- B2 `peakDirty`/`tooltipDirty` 纳入离开确认

- B5 `--fs-16`/`--line` 改用既有 token
- 加 `tools/probe_ui_invariants.py` 把这些钉成回归判据

**验收**：5 条 bug 各有一个失败即转红的判据；无视觉变化。

### 期 1：规范层（视觉统一，不动布局）

- 标题三层 + 20+ 个无标题面板补标题

- 按钮三档提对比
- 复制状态按键分离

**验收**：`probe_a11y.py`（可及名覆盖率、键盘可达率）+ 亮暗两套截图核对。

### 期 2：概览 + 设置重排（收益最大）

- 概览：7 面板 → 3 区块（删「性能健康」、合并「API 信息」+「快速开始」）
- 设置：分区左导航 + 单分区右内容 + 全部即时生效 + 每项状态标记 + 数字框统一走 `onNumInput`

**验收**：概览高度 ≤ 1100px（现 1747）；设置 ≤ 1800px（现 2766）；
`probe_ui_invariants.py` 断言"同一屏内不得出现两种生效语义"。

### 期 3：分析页签细分 + 供应商列表改造

- 分析：2 页签 → 3 页签（用量/省量/性能），诊断进页签内并默认折叠
- 供应商：8 按钮 → 3+⋯菜单；整行点击展开行内摘要；测试结果就地持久

**验收**：供应商"改端点→验证"路径 ≤ 2 层界面、≤ 4 次点击（现 4 层 8 次）。

### 期 4：渐进披露 + 细节工程

- Top-N 溢出、数据量驱动收敛、可见性轮询、陈旧响应守卫、防抖
- sticky 表头实测、tooltip 边缘翻转
- 哈希深链（设置页分区）

### 期 5（可选，需后端）：保存闸门 + 测试指纹

- `POST /admin/api/providers/draft-test`（不落库、返回逐端点结果）
- 指纹：`sha256(protocol|endpoint|endpoints|models|timeout|sha256(key))` 前 16 hex
- 指纹不符 → 前端标"配置已变更，旧测试结果失效"

**注意**：WaLiAPI 的"保存强耦合测试"是它的**缺陷**（网络抖一下就要面对红色弹窗）。
我们采纳"测试凭证"的概念，但**不采纳"必须测试通过才能保存"** —— 允许"仍然保存"，
且离线场景不得阻断。

## 8. 风险与取舍

| 风险 | 说明 | 缓解 |
|---|---|---|
| 改动面大 | 6 个页面 + 3 个 CSS 层 + 20 个 JS 组 | 分期 + 每期独立提交 + 现有探针全跑 |
| 无构建步骤 | 所有改动都要 `cargo build` 才生效 | 已有 `build_preview.py` 预览流程，先预览后提交 |
| 视觉回归 | 亮暗两套主题 | `theme_dark_diff.py`（暗色零变化）+ `theme_contrast.py`（对比度）+ 截图核对 |
| Alpine 响应式陷阱 | 动态新增属性不触发更新（已在 `modelDiagOpen` 踩过） | 统一"重建对象"写法，并写入 `docs/frontend.md` |
| 折叠状态丢失 | 现有 11 个 UI 状态未持久化 | 期 4 统一做"UI 状态持久化注册表"，顺带修 B3 |

**不做的事**（明确划界）：
- 不引入任何打包器/组件库/图表库（保持单 exe 零依赖）
- 不改后端协议（期 5 除外，且单独评审）
- 不为了"好看"加动画（现有 `prefers-reduced-motion` 约束要保留）

## 9. 我建议的起点

**期 0 + 期 1** 先做。理由：

1. 期 0 全是已核实的 bug，修完立刻可用，零设计争议；
2. 期 1 建立规范，是后续所有重排的地基——没有这套规范，重排只会把混乱搬到新布局里；
3. 这两期**不改后端**、不改信息架构，风险最低，且能立刻用探针量化收益。

期 2 之后收益更大但需要你拍板信息架构（尤其"设置页全部改即时生效"这一条会改变操作习惯）。
