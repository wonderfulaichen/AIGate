## 1. 背景与目标

**这是什么**：一个本地跑的 **OpenAI 兼容反向代理** + 桌面管理面板，单 exe 交付。
把多个上游 AI 供应商（DeepSeek / opencode zen&go / CodeBuddy 系 / Ofox / Joule 等）
统一成一套 OpenAI 兼容接口对外暴露，同时做路由、协议转换、Token 优化、成本与用量统计。

- 版本：`0.8.0`（`Cargo.toml:3`）
- 许可证：**GPL-3.0**（`LICENSE`）
- 技术栈：Rust + axum 0.7 + tokio；前端是**编译期内嵌**的 Alpine.js 单页（无构建步骤）
- 交付形态：**单 exe + 系统托盘**，前端全部 `include_str!` 进二进制

**核心目标（按重要性）**：

1. **省 Token** —— 剥离历史推理链、压缩工具输出、响应缓存。这是这个项目的立身之本。
2. **透明** —— 用户能看清"每次请求花了多少、慢在哪一段、省了多少"，且数字必须诚实
   （无数据就显示 `—`，绝不显示 0 假装测过）。
3. **单机零依赖** —— 不装数据库、不依赖外部服务，双击即用。

**谁关心结果**：作者自己（日常用它中转所有 AI 请求）。所以所有设计的隐含前提是
**单人单机、本机 127.0.0.1、没有多用户/多租户需求**。
任何"为多用户设计"的改造（登录页、下游 API Key 体系、权限）都是**跑偏**。

### 4.3 前端是怎么"拼"起来的（**必须理解，否则改了就白改**）

`src/admin.rs:1236-1290`（`concat!`）把 41 个文件**按固定顺序**拼成一个 HTML 字符串，
在**编译期**塞进二进制。关键点：

1. **`ds-*.js` 是 `dashboard()` 对象体的片段**，不是独立文件。
   每个片段里写 `get xxx() {...},` / `method() {...},`，文件之间靠逗号衔接。
   → **在片段里重复声明同名 `const` 会让整段语法错误**，结果是页面上所有方法一起消失
     （表现为几十个 `t is not defined`）。2026-10-26 踩过，构建和单测都不报错。
   → 也**不能**在文件顶部写 `const`（那是对象体内部，会抛 ReferenceError）。
2. **顺序有意义**：`i18n.js` → `stores.js` → `core.js` → `ds-state.js` → 其余 `ds-*`。
   样式表在 `head.html` 之后、`body-shell.html` 之前。
3. **改完前端要 `cargo build` 才生效**（因为是编译期内嵌）。
   确认是否真的重编：**输出里必须有 `Compiling AIGate`** —— 只看 Finished 的耗时不可靠
   （实测未改动时也要 35 秒）。见 §5.5。
   历史上有过"改了没生效"的案例，当时误以为是 cargo 增量跳过，
   后来发现是探针跑的是别处复制的旧二进制 —— **先确认你测的是刚构建的那份**。

探针约定的三件事：
1. **`NODE_PATH` 必须指向 `.openbitfun\tmp\vidtools\node_modules`** —— 探针脚本内部已设好
   （用 `pdir()` 查找）。若自己写脚本，务必设上，否则报 `MODULE_NOT_FOUND`。
2. **探针必须在 `tools/` 目录下** —— `ROOT` 用 `dirname(dirname(__file__))` 计算，
   放 `.openbitfun/tmp/` 会算错根目录。
3. **注入假数据前先停轮询**：`clearInterval(d.pollTimer)`。否则 3 秒一次的 `fetchStats`
   会把注入数据覆盖，表现为**偶发**失败（时好时坏）。

### 5.4 常见故障

| 现象 | 原因 | 处置 |
|---|---|---|
| 页面所有方法失效、满屏 `t is not defined` | `ds-*.js` 里有重复的 `const` 声明 → 整段语法错误 | 检查最近改的片段 |
| 改了 HTML/CSS 但页面没变 | 前端是编译期内嵌，没重新构建；或 cargo 增量跳过 | touch 源文件再 `cargo build`（§5.5）|
| 探针测到"旧页面" | 同上（用的是旧二进制） | 同上 |
| 面板显示 `trend_dim_input` 之类的裸键名 | i18n 键名拼错（正确是 `trend_dim_in`） | `node tools/check_i18n.cjs` 只查对称、不查拼错，需人工比对 |
| 探针 `MODULE_NOT_FOUND: playwright` | 没设 `NODE_PATH` | 见 §5.3 |
| 探针偶发失败 | 3 秒轮询覆盖了注入数据 | `clearInterval(d.pollTimer)` |
| 隔离实例读到的配置是 `zen`/`go`/`deepseek` 这类默认项 | 没把 exe（以及目标 `providers.json`）复制进隔离目录，触发了默认播种 | 见 §5.2 ① |
| `EventLoop can't be recreated` | 想用 wry 在独立线程建窗 | 已改 Win32 原生实现，别退回 wry |
| `cast()` 报 "no method named cast" | `webview2-com` / `windows` 版本与 wry 不匹配 | 锁 0.29 / 0.54 |

### 5.5 改前端后如何确认真的重编了

前端是编译期内嵌（`include_str!`），所以改 HTML/CSS/JS **必须重新 `cargo build`** 才生效。

**判断"是否真的重编"的正确方法 —— 看 `Compiling` 行，不是看耗时：**

```powershell
cargo build --release
# 真的重编了：会出现  Compiling AIGate v0.8.0 (...)
# 只增量跳过：只有     Finished `release` profile ... in 1.6s   ← 且**没有** Compiling 行
```

> ⚠️ 2026-10-31 实测更正：本文早期版本写「`Finished in 1.6s` 就是没重编」，
> 该判据**不可靠** —— 实测不 touch 任何文件时构建也要 35 秒（cargo 会重跑 build script）。
> **可靠判据只有一条：输出里有没有 `Compiling AIGate`。**
>
> 如果确实遇到了"改了但没生效"，先确认 `Compiling AIGate` 出现过；
> 仍不对时再 touch 源文件时间戳强制重编：
> ```powershell
> (Get-Item "src\admin\page-analytics.html").LastWriteTime = Get-Date
> cargo build --release
> ```

## 6. 风险、坑、回滚

### 6.1 不可逆 / 高危操作

| 操作 | 风险 | 怎么做安全 |
|---|---|---|
| 删除 `data/logs.jsonl` | 丢失全部历史明细（rollup 只保留日级聚合） | 先备份到 `data/logs.jsonl.bak` |
| 改 `providers.json` 的模型 ID | 已存日志里的旧 ID 会对不上，历史统计"消失" | 面板改（有 `.bak` 自动备份）；手改先复制 |
| 替换部署目录的 exe | 用户实例需重启，中断所有在飞请求 | **不替用户做**，只给路径与 SHA |
| 改 `rollup.rs` 的字段 | 新字段漏 `#[serde(default)]` → 旧行整行解析失败 → 该天历史静默消失 | 每个新字段都加 default |

### 6.2 已知踩过的坑（按"会静默出错"排序）

1. **`ds-*.js` 重复声明 `const`** → 整段语法错误 → 前端全废。构建、单测都不报错。
2. **`webview2-com` 同进程同 user data folder 建两个环境** → `0x8007139F`。
   登录窗口必须用独立目录（`data/oc_login_webview`）。
3. **探针看 `textContent` 判可见性** → `x-show` 隐藏的元素仍在 DOM，判据恒真（假绿）。
   必须逐祖先查 `display`/`visibility`。
4. **探针用简易 hash 判"图是否不同"** → 小差异会碰撞成同值（假失败）。用完整字符串比。
5. **`_setTrendHtml` 有 160ms 淡入延迟** → 切完立刻读 `modelTrendSvgHtml` 读到**上一版**。
6. **`.ov-page` 被概览页与分析页共用**（分析页另有 `.an-page`）→ 全局查 `.phd`/`.pnl`
   会命中隐藏的那个，量出高度 0。
7. **i18n 占位符是 `{0}`** 不是 `%s`。写错会在界面显示字面量 `省 %s ·`。
8. **`fmtPct` 对 ≥100 会压成 `100%`**（为缓存命中率设计）→ 额度超额必须用专用的
   `ocPctText`，否则 112.5% 显示成 100%。

### 6.3 回滚

- **代码**：`git revert <sha>` 或 `git reset --hard <sha> && git push --force-with-lease`（谨慎）
- **配置**：部署目录有 `providers.json.bak`（每次保存自动生成）+ 三个历史备份
  （`.bak_before_auth` / `.bak_before_buddy` / `.bak_before_preset`）
- **exe**：部署目录有 `旧版本备份\`（**实测含 11 个历史版本**：0.4.2 / 0.4.3 / 0.4.7 /
  0.5.0 / 0.5.1 / 0.5.3 / 0.5.4 / 0.5.5 / 0.5.7 / 0.7.0 / 0.7.2）与 `aigate.old`（5.1 MB）。
  回滚到旧版只需把对应 exe 覆盖上去并重启。

### 9.3 探针的方法学（这个项目的核心资产）

**每条判据都必须做过「改坏验证」** —— 把功能改坏，确认判据转红。步骤：

1. 改坏源码（如把 `x-show` 去掉、把字段填成常量）
2. `cargo build --release`（**必须确认编译成功** —— 编译失败时探针跑的是旧二进制，
   会得到"通过了"的假象；这个坑连续踩过两次）
3. 跑探针，确认**判据失败**（不是编译失败、不是脚本异常）
4. 复原，重新构建，确认转绿

> 历史上有多次「改坏验证不转红」，原因都不是判据无效，而是：
> 改的位置不是探针测的路径（native vs chat）、改的是非流式而探针走流式、
> 或者构建失败。所以每步都要看输出。
